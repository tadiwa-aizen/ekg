\chapter{Results}

This chapter reports the evidence produced by the fixed implementation version described in Chapter 3. It distinguishes four questions that should not be conflated: whether the metrics respond to controlled changes, whether other tools provide the same diagnostic coverage, whether the implementation can run on independently produced RDF event graphs, and whether the implemented formulae agree with hand-computable cases. Interpretation and limitations are developed in Chapter 5.

\section{Evaluation Context}

All proposed-framework results in this chapter were generated with one frozen version of the evaluator. The result records show the input files, settings, software version, and all \FrozenCoreMetricCount{} registered fields. The synthetic and comparator experiments used identical RDF source files. The three controlled profiles are denoted D1 (high quality), D2 (mixed quality), and D3 (low quality). Event-level rates use direct \texttt{sem:Event} instances as their population, and repeated fields are interpreted once. Appendix A provides the detailed provenance record.

The three synthetic datasets test whether the metrics respond to controlled changes. OEKG and ChronoGrapher test whether the same evaluator can run on independently produced RDF event data. The general-tool experiment compares what the tools cover and how their own values respond; it does not combine their incompatible outputs into one score.

\section{Controlled Synthetic Sensitivity}

This experiment tests whether the implemented metrics respond to known changes across the controlled high-, mixed-, and low-quality profiles. It evaluates sensitivity to those interventions; it is not presented as independent evidence that the metrics capture every aspect of EKG quality.

\section{Real-World Feasibility}

The next experiments apply the same fixed evaluator to independently produced RDF event data. The OEKG run tests whether it can process a complete event layer, while the ChronoGrapher runs test how the calculation rules behave on smaller public artefacts with a different representation.

\subsection{OEKG Event Layer}

The complete cleaned OEKG event-layer input contains \OEKGTriples\ triples and \OEKGEvents\ direct \texttt{sem:Event} resources. Only seven invalid backslash escapes in one literals file were repaired to make the N-Triples parseable; the original archive was retained, and no semantic facts were added. The source, cleaned-file, database, projection, and result hashes are recorded in Appendix \ref{app:oekg_run_details}.

\section{Checks That the Evaluator Produced the Defined Values}

All 24 automated tests passed. The tests use small RDF graphs with answers that can be calculated by hand and together cover every registered result field. They include empty and unavailable cases, duplicate normalisation, temporal ordering, type applicability, external-link matching, predicate-distribution formulae, and the structural projection. A fresh reproduction run also regenerated D1--D3 and matched all 32 registered fields for each dataset with the accepted evidence. Appendix A gives the complete test command and verification record.

This result shows that the implementation follows the declared calculation rules for the tested cases. It does not by itself show that every metric is suitable for every EKG or application; that question is considered in Chapter 5.

\section{Results Summary}

The controlled experiment shows that the framework responds to the intended D1--D3 differences and explains why D2 is mixed rather than uniformly poor. The general tools provide useful checks but do not share one defensible score scale. The OEKG and ChronoGrapher runs show that the evaluator can process independently produced RDF event data and report when a calculation does not apply. Together, these results support broader coverage across the selected dimensions and more detailed diagnosis of EKG quality.
